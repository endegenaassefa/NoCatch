# Composing available skills

Depth Engine coordinates the user's outcome. A specialist skill supplies a bounded method or tool; loading it does not delegate scope or authorize side effects. Discover what this host actually exposes, read the selected skill, and use only the capabilities needed for the current phase.

For the bundled methods, execute [native dispatch](native-dispatch.md). The registry points to downloaded implementations with licenses, supporting files and hash inventories; selected skill text is embedded in the worker task, not merely mentioned as a web link. For a direct task, read the applicable local vendor entrypoint and its registry adaptation yourself. Do not load every bundle. Existing installed Product Design/connector skills remain available through the host catalog and should be used when their actual trigger applies.

| Need | Select if available | Boundary |
| --- | --- | --- |
| UX audit, visual exploration, faithful design implementation | Product Design entrypoint, then its selected workflow | Respect its task trigger; ordinary frontend coding need not become a design audit |
| Raster artwork | Image-generation skill/tool | Use for actual image assets; code/vector-native work stays native |
| Connected documents or spreadsheets | Relevant installed connector skill | Limit reads/writes to the requested files and task |
| Provider-specific infrastructure, framework or API | Relevant stack skill and current official docs | Verify host capabilities and version; no invented integrations |
| Creating or improving a skill | Skill-creator guidance | Preserve invocation policy and evaluate behavior |

These are capability descriptions, not guaranteed installed dependencies. Use the host's current catalog to resolve exact paths. If a useful skill is missing, use verified tools and the domain reference or report the specific capability gap. Do not bulk-install skills from a popularity list. Inspect a third-party skill's content/dependencies before any authorized installation; a directory listing is discovery, not quality certification.

Resolve overlap deliberately: the user sets the outcome and authorization; host/system rules control tool access; repository instructions control local conventions; Depth Engine retains its task coordination and QA ownership; the specialist contributes its method within those constraints. If two methods conflict, preserve higher-priority instructions and the stricter applicable frozen contract, explain material adaptations, and avoid silently executing both coordinators. Ask only when the conflict requires an unresolved user choice.

For example, a TDD skill that lets the builder author tests must be adapted to QA-authored checks under Depth Engine. A publishing step in an imported skill cannot authorize a public post. Cursor-specific `/loop` commands do not install a Codex/Claude supervisor.

Give delegated work a narrow packet: outcome, relevant requirements/decisions, readable artifact pointers, allowed write paths, verified tools, finish evidence and stop condition. Do not pass the entire conversation or every loaded skill. Use one owner for shared source; the current runtime does not implement parallel worktree integration. Prefer a direct task over a manager that creates more managers.

Sources: [Matt Pocock's skill collection](https://github.com/mattpocock/skills), [pstack](https://github.com/cursor/plugins/blob/main/pstack/README.md), and [Cursor's scaling experiments](https://cursor.com/blog/scaling-agents). Their orchestration patterns are references, not installed features or permission grants.
