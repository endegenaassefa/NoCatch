**OpenCluely: Windows/macOS setup blueprint**

This design companion gives product and engineering an incremental route to one automatically adapting app for users without developer tools or provider accounts. Managed sign-in with operator-funded AI and **full P01–P21 parity** are inherited [repository-recorded requirements](../CROSS-PLATFORM-DESIGN.md#product-contract). This document proposes work; it implements nothing.

Observations below refer to the 2026-09-22 [source snapshots and manifest](.depthengine/evidence/source-manifest.json). Repository links navigate the original files, which may subsequently change. The [captured design](.depthengine/evidence/source/docs/CROSS-PLATFORM-DESIGN.md) preserves the decision baseline.

**Observed starting point.** Retain Electron and vanilla HTML/JavaScript. [package.json](../../package.json) pins candidate Electron 44.4.4/builder 26.15.3 and configures Windows x64 NSIS/portable and Intel/Apple Silicon Mac DMG/ZIP; configuration does not establish support. [Managed desktop sessions](../../src/managed/index.js) and a [server implementation](../../server/README.md) already exist, superseding older statements that managed services are unimplemented. Operator provisioning is required; deployed availability is unverified. No hosted transcription path is documented. The backend is a single-instance SQLite pilot, without horizontal scaling.

[preload.js](../../preload.js) exposes signIn/getManagedStatus/getSetupCapabilities/testSetupAnswer; [main.js](../../main.js) wires them and defaults to managed AI. Yet [onboarding.js](../../onboarding.js) still leads through API keys, speech-provider selection and Python/Whisper installation. The [captured browser observation](.depthengine/evidence/browser-observed.txt) confirms the API-key screen. The greeting-only setup test proves neither capture nor microphone readiness. [managed/config.js](../../src/managed/config.js) loads packaged managed-config.json, absent from the explicit package allowlist. These are integration gaps, not reasons for a rewrite.

**Proposed user journey.** Offer one account and consistent navigation. Download detection is best effort, with explicit OS/CPU alternatives; validate compatibility at install/startup. Prefer signed Windows NSIS and signed/notarized Mac DMG, retaining qualified archive/portable options under Electron's [distribution](https://www.electronjs.org/docs/latest/tutorial/distribution-overview) and [signing guidance](https://www.electronjs.org/docs/latest/tutorial/code-signing). No end-user Node, Python, pip, compiler, Homebrew, PATH or environment-variable setup. Preserve the light UI, one primary action, visible keyboard focus, accessible status announcements and readable layouts in small windows/enlarged text.

| Screen/state | Primary action and observable outcome | Recovery/platform adaptation |
|---|---|---|
| Welcome / signed out | “Sign in” opens the system browser; show waiting and Cancel. Return to the pending task after authentication. | Cancellation, timeout or failed callback offers Retry without losing preferences. |
| First action | “Try a screenshot”: choose display/region or a bundled sample, preview, disclose upload to the managed service/provider, then ask a question. Text-only is also available. | Ask screen permission only for actual capture. Sample/text success never marks screen capture healthy. |
| Permission / capturing | Explain the requested capability before invoking its OS flow; show progress and Cancel. | macOS screen consent/settings differs from microphone prompting: Electron's [askForMediaAccess](https://www.electronjs.org/docs/latest/api/system-preferences#systempreferencesaskformediaaccessmediatype-macos) has no screen equivalent. Windows requires a real capture test and version-appropriate privacy guidance. Never treat unknown permission as success. |
| Success | Show the real answer; “Start using OpenCluely.” Offer “Enable voice” and advanced options later. | Readiness reflects only successfully exercised features; optional onboarding does not make release features optional. |
| Denied / restricted | “Open Settings,” explain the relevant control, then “Check again.” | Avoid prompt loops; restriction may require administrator action. Denied microphone leaves text/capture available; denied screen leaves text/sample available. |
| No device / changed display | Choose another microphone/display or reconnect it. | Recheck devices; invalidate stale regions and ask for reselection, never silently capture a larger area. |
| Native helper unavailable | Explain the affected feature and offer Repair. | Distinguish missing/incompatible helper, permission denial and an OS block. Verify the replacement, end affected input sessions and restore ordinary input; other usable features remain available. |
| Offline / service failure / quota | Preserve the step and draft; show Retry or the reported usage limit. | Reconnect to an accepted request by ID; do not silently bill another attempt. After the packaged runtime and model are installed and verified, local transcription remains usable offline. |
| Restart / update / interrupted download | Resume the exact step after rechecking prerequisites. | Defer update restart during work; retain preferences and valid assets. Offer repair for failed installation; low disk or corrupt assets get actionable retry. |

Voice activation separately exercises real microphone audio, transcript and selected answer destination, then stops streams/workers and cleans temporary audio. State clearly whether recognition is local or cloud; never upload audio implicitly. Session expiry gets one coordinated refresh, then sign-in on revocation. Unavailable secure storage offers session-only sign-in, never plaintext tokens. An unconfigured build needs a corrected release, not user credentials.

Cancellation before submission spends no request allowance. Explain that an accepted request can consume allowance even if cancelled or failed; reconcile its status before offering a consciously new request. Never describe cancellation as a refund.

**Proposed engineering responsibilities.** Shared UI → validated narrow preload → application/setup service → platform adapters/native helpers; application services also call the managed API and packaged local speech process.

| Owner / existing boundary | Next responsibility |
|---|---|
| Desktop UI: onboarding.js and preload.js | Connect account/first-action state to the main-process [first-run service](../../src/core/first-run.js). Default packaged builds to managed AI; expose retained direct-key mode through Advanced Settings with persisted configuration, never a user-edited environment variable. Validate IPC senders/inputs and clean event subscriptions. |
| Main/setup: main.js, [platform/index.js](../../src/platform/index.js), [capture.service.js](../../src/services/capture.service.js) | Introduce one setup service and share one adapter instance between onboarding and real capture; currently they use separate instances. Feed actual operation outcomes back into setup. Replace blanket keep-alive error handling with explicit service failure/cleanup; unknown main-process failures must invalidate health and offer safe restart. |
| Identity/backend: src/managed and server | Main owns tokens, OS-backed refresh storage and external-browser PKCE following [native OAuth](https://www.rfc-editor.org/rfc/rfc8252). Operators provision HTTPS, OIDC/native callback contract, audience/scopes, provider billing, quotas and retention; provider secrets stay server-side. Add managed Azure speech. |
| Speech/packaging: [whisper-installer.js](../../src/core/whisper-installer.js), package.json | Replace system-Python/venv/pip dependency with a versioned private runtime per OS/CPU. Compare engines through accuracy, latency and settings-compatibility measurements. Reuse renderer microphone capture for both local and managed speech; remove reachable sox/rec/arecord requirements on Windows/Mac. Preserve Linux capture and deb dependencies until separately migrated/tested. |
| Main-process lifecycle/update service; release pipeline | Implement pinned, compatible electron-updater integration, trusted update metadata/signatures, idle-time restart and repair. The setup service checkpoints progress; this owner coordinates shutdown/resume with audio, input helpers and migration. Build/sign every architecture-specific helper and reject missing or incompatible resources. |

Normalize the older design contract at the proposed setup-service boundary. Use the adapter's actual availability `available/unavailable/unsupported`, permission `not-determined/granted/denied/restricted/unknown`, and health `untested/healthy/failed`; expose in-progress operations separately. These do not already match the older `supported/not-requested/ready` terminology. Keep account, capability, assets and onboarding progress independent. Persist versioned progress/preferences and verified asset metadata; recheck account, permissions, devices and operation health at launch, Settings return and feature use. Reset stale operation health on restart; permission grants alone cannot establish health.

Builds must include and validate public managed-config.json inside the archive, failing release packaging when missing/invalid. Ship checksummed, resumable model downloads with disk checks, staging and atomic activation; retain working assets until replacement passes transcription. Require CPU fallback and offline recognition after download. Preserve model/language/device, manual/VAD, segmentation, output targets and custom-runtime options; hardware acceleration needs qualification.

Centralize data paths and stable signing/storage identity before migration. Current internal names are `screen-reader-util` and `com.screenreaderutil.app`, while artifacts use OpenCluely. Keep installed identity stable unless an explicit migration is validated; visible branding must not silently change userData or permission/signing identity. Journal versioned migrations across Electron userData, ~/.screen-reader-util, legacy .env/sentinel files and speech assets; back up preferences, verify readback and preserve originals on failure. Resolve conflicting profiles explicitly. Protect retained user keys without uploading them; preserve compatible models and advanced settings. Define history retention explicitly. Do not discover arbitrary working-directory credentials in production. Add sign-out and a separate confirmed “Remove local data” action covering tokens, history and models; disclose that current NSIS uninstall retains app data and document server-retained data separately.

**Proposed delivery sequence and release gates.**

1. Extend existing packaging into a signed qualification baseline while completing the managed vertical slice in parallel. Candidate envelope: Windows 11 x64 and Intel/Apple Silicon Mac. Exact tested OS boundaries and Windows ARM64 remain unresolved; configured macOS 13 minimum is not qualification. **Exit:** freeze that support matrix and installed identity; install and launch a signed Windows build and signed/notarized Mac builds on every selected CPU/OS boundary; verify helper architecture/signatures and permission-denial recovery without developer tools. Record scenario-based P15–P19 verdicts (focusless input, capture exclusion, identity, privileged lifecycle and shield transitions), with expected/observed outcomes. Unsupported outcomes block the full release; unresolved feasibility blocks broad native implementation. Existing evidence establishes no signed baseline.
2. After the backend owner provisions and live-tests the pilot tenant/API and the release owner produces Stage 1 artifacts, connect actual onboarding, packaged deployment config and shared setup state. Exit: clean packaged installs on both OSes sign in and produce an answer from the selected display/region without local keys/tools. Validate provider/input compatibility; the documented server accepts images through Gemini, while DeepSeek is text-only.
3. Add managed voice and packaged local runtime; complete every [P01–P21 row and retained setting](../CROSS-PLATFORM-DESIGN.md#source-inventory-and-parity-requirements). Dependencies include service provisioning and native feasibility. Exit: equivalent observable outcomes, including local speech, focusless input, capture protection, identity behavior, privileged lifecycle and shield transitions. Unsupported required outcomes block release rather than disappearing behind disabled controls.
4. Implement and qualify installs/upgrades, migration, recovery and [updater integration](https://www.electron.build/v26/docs/features/auto-update/). package.json has no electron-updater dependency; artifact metadata is not an updater. **Exit:** previous-version upgrade and interrupted-update repair preserve settings, drafts and compatible models; no restart interrupts recording or a request; sign-out and local-data removal work. Cover clean accounts, advertised OS boundaries, every CPU, mixed-DPI displays, keyboards/IME, permission revocation, helper crashes and outages. Preserve the existing Linux target; this Windows/Mac design does not qualify it.

Native limits remain gates: recorded [capture-protection caveats](../CROSS-PLATFORM-DESIGN.md#feasibility-gates-before-broad-implementation) include [Electron's ScreenCaptureKit limitation](https://www.electronjs.org/docs/latest/api/browser-window#winsetcontentprotectionenable-macos-windows); universal invisibility cannot be promised. Use documented OS interfaces and scoped compatibility evidence. Signing cannot promise [warning-free Windows installation](https://learn.microsoft.com/en-us/windows/apps/package-and-deploy/smartscreen-reputation). Advanced privilege requirements must be explicit, with denial/recovery tested.

**Evidence limits and measurement.** The coordinator [recorded 40 passing WSL/Linux fixture tests](.depthengine/evidence/checks-observed.txt); these establish no deployed identity/provider or native desktop behavior. [BUILDING.md](../BUILDING.md) records earlier unsigned Windows build/startup checks; they were not rerun here. No Mac hardware qualification or proposed signed-out journey was executed. The setup/lifecycle owner measures time to first useful answer, abandonment, repeated prompts and dependency failures locally by default. Offer a previewed, redacted support export; remote analytics requires an explicit product/retention decision and user choice. Establish targets from observations, not setup-time promises.

**Prerequisites and unresolved contracts.** These are required engineering work, not evidence of current availability.

- The release owner must obtain publisher/Apple signing access and Windows/Mac runners plus target hardware before scheduling signed qualification. First sub-check: build/install/launch one signed artifact per architecture; then expand to OS boundaries and the native scenarios. Credential access and Mac hardware are unverified here.
- The platform owner must establish the Windows native input/helper architecture through a documented-API prototype, select the toolchain, and add per-architecture Windows helper packaging/signing and authenticated lifecycle IPC. No Windows P15/P19 helper is evidenced by the current package configuration. Repair belongs jointly to this owner and the lifecycle service. This is a major feasibility gate, not a presumed port of Mac root mode. Keep the ordinary networked GUI unelevated; any justified helper privilege requires a separately tested design.
- The backend owner must deploy OIDC/native PKCE registration, public packaged configuration, funded providers, HTTPS/SSE ingress and persistent request storage before the managed first-action test. Start with an invited pilot sized to the single-instance store; general availability needs a measured capacity, availability, backup/restore and support plan.
- Proposed managed-voice contract: authenticated transcription sessions with start/stop/cancel, bounded audio chunks and duration, ordered interim/final transcript events, device-loss/disconnect cleanup and explicit audio-minute usage. The backend owner sets published limits before enabling voice. Do not persist audio by default; disclose provider handling and transcript retention. Stage 3 must verify stop flushes once, cancel suppresses late output, duplicate starts do not double-charge, and quota usage matches accepted audio.
- Explain in Settings that the current backend retains responses/events for 24 hours by default, sign-out/local deletion does not erase server records, and already-issued access tokens may survive identity-provider logout until expiry. On shared-device sign-out, close requests, clear credentials/cached account content and prevent stale replies from appearing after account change. Any server deletion feature needs its own authenticated contract.
- For failed Windows capture, use evidence-backed causes: missing display/source means reselect, known permission denial means Settings, known policy restriction means administrator guidance. Unknown backend failure stays “Capture failed” with Retry and redacted diagnostics; never invent a permission diagnosis.
